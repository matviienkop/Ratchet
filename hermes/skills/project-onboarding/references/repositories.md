# Change an existing project's repositories

Use the project named in the conversation. If several projects match, ask which one. Resolve a shorthand name against the declared repositories using `ai-dev project status --project SLUG`. Exit 1 still returns the list and includes pending checkouts. If asked to list repositories, report their paths, origins and checkout status and stop.

- **Add.** Use the repository URL supplied in chat. When given only a name with no established origin, ask for its URL. Match an existing declaration by origin and reuse its checkout path on retries. Run `ai-dev project repo-add --project SLUG --url URL`. Pass `--path PATH` for an explicit or existing checkout location and `--role ROLE` for an owner-supplied description. Paths are relative to the project's repos directory. An inaccessible declared origin can be retried with the same request after read access is available.
- **Remove.** Resolve the owner's URL or name to one declared path. Ask for the exact checkout if the name is ambiguous. Run `ai-dev project repo-remove --project SLUG --path PATH`. This removes membership and keeps the local working copy, including uncommitted work. Report its location if retained. If a parent has registered children, report the paths and ask which members the owner wants removed. Keep other memberships intact. Remote repository deletion and local file cleanup are separate operations outside this command.
- **Refresh.** After a change or retry, run `ai-dev-analyze PROJECT_DIR inventory`. For a newly added checkout that needs analysis, delegate only that checkout and revision using the [research assignment](research.md). Reuse current evidence for other members. Run `ai-dev-analyze PROJECT_DIR finalize --partial` to regenerate the working documents and inferred settings. With full coverage this publishes the local canonical outputs. With pending sources it writes the active preview under `provisional/` and returns exit 2. Report the returned output root, outstanding sources, conflicts and retained task cards that need review. Workers take their checkout scope from current membership, including when a detached working copy still exists on disk.

Use these commands directly from chat. Rediscovering the organization can reintroduce sources the owner removed. Quote chat values as individual command arguments and keep credentials out of origins and messages.

Apply the same style discovery on repo-add as on initial registration. For a new empty repository, save the default for its declared stack using the greenfield step in the onboarding skill. Inventory will request source analysis after the first commit.
